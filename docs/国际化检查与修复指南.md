# iOS 国际化检查与修复指南

> 目的：统一记录如何**系统性检查**缺失的国际化 key、如何**规范校验**、以及如何**正确修复**，避免每次靠肉眼翻代码，也避免补充时出现格式/语义错误。本文件为团队通用 SOP。

---

## 一、背景：三类"国际化没做好"问题

在实际排查中，iOS 项目里 `Localizable.strings` 的国际化问题通常分为三类：

| 类型 | 现象 | 示例 |
|------|------|------|
| **A. 值 == key** | key 已定义，但 `value` 直接填了 key 名，未翻译 | `"order_cancel_confirm_msg" = "order_cancel_confirm_msg";` |
| **B. key 缺失** | 代码里用了 `Text("xxx")`，但语言文件里根本没有这个 key | 代码 `Text("order_actions_title")`，.strings 无定义 |
| **C. 硬编码文案** | 代码直接用中文/英文原文，没走 key 化 | `Text("暂无崩溃日志")`、`Label("请求", systemImage: "arrow.up")` |

> SwiftUI 的 `Text("xxx")`、`Label("xxx", ...)`、`.alert("xxx")`、`navigationTitle("xxx")` 接收的字符串字面量会作为 `LocalizedStringKey` 自动本地化。**只要语言文件里定义了对应 key，就能翻译**；否则直接显示 key 原文或硬编码文本。

---

## 二、检查方法（典型格式正则校验）

### 2.1 提取代码中引用的所有本地化 key

代码里引用 key 的典型形式有三种，用 `rg` 正则提取：

```bash
cd <项目目录>

# 1) Text("key") — SwiftUI 字面量本地化
rg --no-filename -o 'Text\("([a-z][a-z0-9_]+)"\)' . --glob "*.swift" -r '$1'

# 2) NSLocalizedString("key", ...)
rg --no-filename -o 'NSLocalizedString\("([a-z][a-z0-9_]+)"' . --glob "*.swift" -r '$1'

# 3) LocalizedStringKey("key") / 或接受 LocalizedStringKey 的字面量
rg --no-filename -o 'LocalizedStringKey\("([a-z][a-z0-9_]+)"' . --glob "*.swift" -r '$1'
```

合并去重，得到"代码实际用到的 key 集合"：

```bash
rg --no-filename -o 'Text\("([a-z][a-z0-9_]+)"\)' . --glob "*.swift" -r '$1' \
  > /tmp/ck.txt
rg --no-filename -o 'NSLocalizedString\("([a-z][a-z0-9_]+)"' . --glob "*.swift" -r '$1' \
  >> /tmp/ck.txt
rg --no-filename -o 'LocalizedStringKey\("([a-z][a-z0-9_]+)"' . --glob "*.swift" -r '$1' \
  >> /tmp/ck.txt
sort -u /tmp/ck.txt -o /tmp/ck.txt
```

> ⚠️ 若代码中自定义组件接受 `title: String` 再内部 `Text(LocalizedStringKey(title))`（如 `iconLabel(title:)`），也要把对应调用处的字面量提取出来，补一条正则：
> ```bash
> rg --no-filename -o 'title: "([a-z][a-z0-9_]+)"' . --glob "*.swift" -r '$1' >> /tmp/ck.txt
> ```

### 2.2 提取语言文件中已定义的 key

```bash
grep -oE '"([a-z][a-z0-9_]+)" =' <语言>.lproj/Localizable.strings \
  | sed -E 's/"([a-z][a-z0-9_]+)" =/\1/' | sort -u > /tmp/lang_keys.txt
```

### 2.3 比对得出缺失 key

```bash
comm -23 /tmp/ck.txt /tmp/lang_keys.txt
```

输出即为**代码引用了、但该语言文件没有定义**的 key（对应问题 B）。分别对 `en.lproj` 和 `zh-Hans.lproj` 各跑一次。

### 2.4 检查"值 == key"的未翻译条目（问题 A）

```bash
# 找出 value 与 key 完全相同的行（即未翻译）
grep -E '^"([a-z][a-z0-9_]+)" = "\1";$' <语言>.lproj/Localizable.strings
```

> 也可用正则反向匹配，找出 `"key" = "中文/英文原文"` 中 value 看起来仍是 key 的行。

### 2.5 检查"硬编码中文"（问题 C）

```bash
# 找出 Text/Button/NavigationTitle/Label/.alert 等中的中文硬编码
rg --no-filename -o '(Text|Button|NavigationTitle|Label|SectionHeader|LabeledRow|\.alert|\.confirmationDialog)\([^)]*[\x{4e00}-\x{9fa5}][^)]*\)' . --glob "*.swift"
```

> 若想更全，可加 `-r` 捕获完整行再 `sort | uniq -c | sort -rn` 统计出现次数。

## 三、处理流程：先校对，再补充

**原则：拿到缺失 key 后，必须先确认它在代码/UI 中的真实含义，再给出准确翻译，切勿凭 key 名猜文案。** 尤其是含 `%@` 占位符、`%d` 数字的 key，翻译必须保留占位符。

### Step 1 — 定位 key 在代码中的使用场景

```bash
rg -n '"<key>"' <代码目录> --glob "*.swift"
```

查看上下文，确认：
- 它是**按钮文案 / 弹窗标题 / 提示消息 / 占位符**中的哪一类；
- 是否含 `%@`、`%d`、`%ld` 等格式化占位符；
- 语气、称谓（你/您）、标点（全角/半角）是否符合界面规范。

### Step 2 — 确认语义后写中英文翻译

示例：

| key | 使用场景 | 中文 | 英文 |
|-----|---------|------|------|
| `order_pay_confirm_msg` | 支付确认弹窗，含金额 `%@` | 将支付 %@，请确认 | You will pay %@. Confirm? |
| `order_cancel_confirm_title` | 取消订单弹窗标题 | 取消订单 | Cancel Order |
| `pay_success_order_id` | 支付成功页字段标签 | 订单号 | Order ID |

> **含占位符的 key，翻译必须保留占位符**，否则运行时 `String(format:...)` 会崩溃或显示异常。

### Step 3 — 补齐到两个语言文件

- **en.lproj/Localizable.strings**：英文
- **zh-Hans.lproj/Localizable.strings**：中文（简体）

按字母序插入到对应字母区域的合适位置，保持文件可维护。

### Step 4 — 处理硬编码文案（问题 C）

把代码中的硬编码替换为 key 字面量，再按 Step 1-3 补齐：

```swift
// 修改前
Text("暂无崩溃日志")
Label("请求", systemImage: "arrow.up")
iconLabel(icon: "x", color: .orange, title: "崩溃日志")   // title: String → 内部 LocalizedStringKey(title)

// 修改后
Text("crash_log_empty")
Label("api_log_request", systemImage: "arrow.up")
iconLabel(icon: "x", color: .orange, title: "crash_log_title")
```

> 注意组件签名：若自定义组件参数是 `String` 且内部不转 `LocalizedStringKey`，需用 `NSLocalizedString("key", comment: "")` 传 String；若内部已 `Text(LocalizedStringKey(title))` 或用 SwiftUI 内置 `Text/Label/.alert`，直接写字面量 key 即可。

### Step 5 — 复核（改动完成后必做）

```bash
# 1) 重新比对，确认无缺失
comm -23 /tmp/ck.txt /tmp/lang_keys.txt   # 应为空

# 2) 确认"值==key"已清零
grep -E '^"([a-z][a-z0-9_]+)" = "\1";$' <语言>.lproj/Localizable.strings   # 应为空

# 3) 确认硬编码中文已清零
rg --no-filename -o '(Text|Button|NavigationTitle|Label|SectionHeader|LabeledRow|\.alert|\.confirmationDialog)\([^)]*[\x{4e00}-\x{9fa5}][^)]*\)' . --glob "*.swift"   # 应为空

# 4) 确认新增 key 在两种语言文件都有
for k in <key1> <key2>; do
  e=$(grep -c "\"$k\" =" en.lproj/Localizable.strings)
  z=$(grep -c "\"$k\" =" zh-Hans.lproj/Localizable.strings)
  [ "$e" -eq 0 ] || [ "$z" -eq 0 ] && echo "缺失: $k"
done
```

## 五、注意事项 / 踩坑记录

1. **`.strings` 文件不要求排序**，但按字母序组织更利于维护；插入时保持同一前缀（如 `order_`、`crash_log_`）聚在一起。
2. **占位符必须保留**：`%@`（任意对象）、`%d`/`%ld`（整数）。翻译时位置可调整，但数量必须一致。
3. **`Text("key")` vs `NSLocalizedString("key")`**：
   - SwiftUI 内置 `Text/Label/Button/.alert/navigationTitle` 的字面量参数是 `LocalizedStringKey`，写 key 名即可自动本地化；
   - 自定义组件接收 `String` 参数时，要么内部 `Text(LocalizedStringKey(x))`，要么调用处用 `NSLocalizedString`。
4. **同一视图可能有多套重复实现**（如 `CrashLogsView.swift` 与 `SettingsView.swift` 内都定义了崩溃日志视图），修改时要**全部同步**，避免遗漏一处仍显示硬编码。
5. **归档/验证目录也要同步**：项目内可能存在历史快照/归档目录，涉及国际化改动时应确认是否一并同步，防止代码漂移。
6. **中英文都要补**：只补一种语言，另一种语言会退化为显示 key 名。收尾必须用 `comm` 分别对 `en`/`zh-Hans` 各核对一次。
7. **验证硬编码清零**：`rg` 扫描中文的正则依赖 `[\x{4e00}-\x{9fa5}]` 中文字符区间，Mac/Linux 的 ripgrep 均支持；若字符串跨行，可加 `--multiline`。
